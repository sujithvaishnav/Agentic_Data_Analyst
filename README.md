# Agentic Data Analyst Pipeline

A **LangGraph-powered multi-agent system** for automated data analysis and reporting,
with a built-in evaluation framework that scores every run.

---

## Folder Structure

Arrange the files **exactly** as shown below:

```
agentic_pipeline/           ← project root (run all commands from here)
│
├── main.py                 ← entry point
├── state.py                ← PipelineState TypedDict (shared memory schema)
├── llm_client.py           ← Groq API wrapper
├── requirements.txt
├── .env.example            ← copy to .env and add your key
│
├── config/
│   ├── __init__.py
│   └── settings.py         ← GROQ_MODEL, MAX_ITERATIONS, VALID_NODES, OUTPUTS_DIR
│
├── agents/
│   ├── __init__.py
│   ├── goal_interpreter.py ← node 1: user query → goal sentence
│   ├── planner.py          ← node 2: goal → ordered step plan
│   ├── router.py           ← node 3: hybrid routing (rule-based + LLM fallback)
│   ├── analyst.py          ← node 4: generates and queues Python analysis code
│   ├── researcher.py       ← node 5: validates and cross-checks findings
│   ├── writer.py           ← node 6: composes final Markdown report
│   └── critic.py           ← node 7: scores output 0-10, loops or ends
│
├── tools/
│   ├── __init__.py
│   └── executor.py         ← sandboxed Python runner (Pandas / Matplotlib)
│
├── memory/
│   ├── __init__.py
│   └── shared_memory.py    ← checkpoint save/load + state pretty-printer
│
├── evaluation/
│   ├── __init__.py
│   ├── metrics.py          ← RunMetrics dataclass + event types
│   ├── collector.py        ← hooks that populate metrics from pipeline state
│   ├── scorer.py           ← scores metrics into 5 dimensions (0-100 each)
│   ├── reporter.py         ← terminal report + evaluation_report.md
│   └── history.py          ← persists runs to eval_history.jsonl
│
└── outputs/                ← auto-created on first run
    ├── final_report.md     ← the analysis report
    ├── evaluation_report.md← scored evaluation in Markdown
    ├── eval_history.jsonl  ← one line per run, append-only
    ├── *.png               ← generated plots
    └── checkpoints/
        └── checkpoint_*.json
```

## Setup (one-time)

### 1. Create and activate a virtual environment

```bash
# Windows
python -m venv myenv
myenv\Scripts\activate

# Mac / Linux
python3 -m venv myenv
source myenv/bin/activate
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Set your Groq API key

```bash
# Copy the template
cp .env.example .env

# Open .env and set your key:
# GROQ_API_KEY=your_key_here
```

Get a free key at **https://console.groq.com**

## Running the Pipeline

### Synthetic dataset (no CSV needed)

```bash
python main.py
```

### Custom query

```bash
python main.py --query "Find seasonal trends and revenue anomalies in my sales data"
```

### With your own CSV dataset

```bash
python main.py \
  --dataset "C:\path\to\your\data.csv" \
  --query "Analyse car purchase amounts and find statistical patterns"
```

**Windows path example:**
```bash
python main.py --dataset "D:\Projects\data\sales.csv" --query "Find top revenue months"
```

### View evaluation history (all past runs)

```bash
python main.py --history
```

## Evaluation Framework

Every run is automatically scored across **5 dimensions**:

| Dimension | Weight | What it measures |
|-----------|--------|-----------------|
| Output Quality | 30% | Critic score, report length, plots, findings depth |
| Pipeline Performance | 25% | Goal met, iteration budget used, plan completion |
| Routing Efficiency | 20% | Rule-based %, invalid agent suggestions, agent diversity |
| Execution Reliability | 15% | Code success rate, failure recovery, retries |
| Resource Efficiency | 10% | LLM call count, agent latency |

## Configuration

Edit `config/settings.py` to tune behaviour:

```python
GROQ_MODEL     = "llama-3.1-8b-instant"   # Groq model to use
MAX_ITERATIONS = 8                             # hard ceiling on agent loop
VALID_NODES    = ["analyst", "researcher", "writer"]
OUTPUTS_DIR    = "outputs"
```

**Tuning MAX_ITERATIONS:**

```
Minimum safe value = number of plan steps + 2
Simple query  (2-3 steps) → 5
Standard      (4-6 steps) → 8   ← default
Complex       (6+ steps)  → 12
```

## How the Hybrid Router Works

```
Router fires each iteration:
  Step 1 → Rule-based check (deterministic, no LLM call)
    Rule 1: final_report exists + goal_met → END
    Rule 2: iteration >= MAX-1 → force writer
    Rule 2b: last execution failed → retry analyst
    Rule 3: follow plan[plan_step_index] → that agent
    Rule 4: critic needs_work + plan exhausted → defer to LLM
    Rule 5: plan done + no report → writer
  Step 2 → LLM fallback (only if rules inconclusive)
    Sends compact context dict (~200 tokens) to Groq
    Validates response against VALID_NODES whitelist
```

~80% of routing decisions are handled by rules — LLM is only called when
the state is genuinely ambiguous.

## Key Design Decisions & Bug Fixes

### 1. `**state` spread bug (state bloat)
**Problem:** Every agent returning `{**state, "messages": [new]}` caused LangGraph
to double-append the `messages` list every iteration (399 duplicates from 5 runs).

**Fix:** Every agent returns ONLY the fields it changed — no `**state` spread.
LangGraph accumulates `Annotated[list, operator.add]` fields automatically.

### 2. `DATASET_PATH` injection
**Problem:** LLM hardcoded CSV paths in generated code → `FileNotFoundError`.

**Fix:** `dataset_path` is stored in `PipelineState` and injected into the
sandbox namespace as the variable `DATASET_PATH`. LLM code always uses
`pd.read_csv(DATASET_PATH)`.

### 3. Iteration ceiling not enforced
**Problem:** Pipeline ran to 16+ iterations despite `MAX_ITERATIONS = 8`.

**Fix:** Hard ceiling check added to `critic_edge()` in `main.py`.
Both the router and the critic edge enforce the limit independently.

### 4. Pandas 3.x frequency aliases
**Problem:** LLM generates `freq='M'`, `freq='Q'` etc. — removed in Pandas 3.x.

**Fix:** Two-layer defence:
  - `_patch_freq_aliases()` in executor.py patches them before `exec()`
  - Analyst prompt explicitly lists the correct aliases

### 5. `plan_step_index` tracking
**Problem:** Router counted agent roles to track plan progress — failed for plans
with multiple analyst steps (e.g. analyst, analyst, researcher, writer).

**Fix:** `plan_step_index: int` added to state. Router advances it by 1 each time,
indexing directly into `plan[step_idx]` instead of counting role names.
